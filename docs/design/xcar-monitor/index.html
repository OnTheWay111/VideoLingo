01 / 页面结构与视觉

浅灰画布、白色信息卡、松绿色主色；蓝灰表示辅助信息，琥珀色标记待确认与缺失。首屏按「产出 → 消耗 → 环节 → 单条证据」组织。桌面四列指标卡，手机两列；宽表横向滚动。

本轮交付是独立 HTML 视觉稿，不启动候选生产或发布。可切换两条 Token 链路、两类明细及 Token 未采集状态，点「详情」查看任务归因。正式版本建议独立本地 Web 页面与 Python 只读 API，复用现有脚本与状态文件；无需修改 VideoLingo 主界面。

03 / Token 分阶段与真实归因

搜索与入池：选题与检索策略 → 搜索筛选 → 下载/抽帧协助 → 画面与事实审核 → 文案、定稿与入池。发布：计划与预检 → 上传与提交协助 → 结果核验 → 链接补查与恢复。

下载、ffmpeg、去重和普通浏览器脚本不直接消耗模型 Token；Agent 读工具结果、图片及决定后续操作的调用才产生用量。零值只有在采集覆盖完整且确认无模型调用时显示。未采集显示「—」，部分采集显示「已观测 32.1k / 数据不完整」，禁用误导性的完整占比。

以宿主返回的逐调用 usage 为准，保存 provider、model、request_id、run_id、job_id、flow、stage、source_id（可空）、attempt、started_at、completed_at、input_tokens、cached_input_tokens、output_tokens、reasoning_tokens、usage_source、quality。缓存输入通常属于 input 子集，推理通常属于 output 子集；适配器先归一化，不能重复累计。

request_id 幂等去重；失败有 usage 也记账，失败无 usage 标未知。仅有会话累计值时校验差分、重置与重复事件，不能把整个会话用量重复算给每一步。调用跨阶段无法精确拆分时记「未归因」，共享调用不复制到多个视频。只给出任务/阶段级用量，不伪造逐视频精度。

Token 按 completed_at 归到自然日；跨午夜的一次调用归完成日。任务详情另显示全生命周期总量，与当天消耗区分。跨日任务的各阶段计数不强行按漏斗比例解读。若宿主不提供 usage 或阶段关联，业务统计仍可用，Token 保持缺失，后续新增执行适配器。

04 / 数据接入与实现边界

  1. 业务读取层：只读读取队列、发布历史和 candidate_jobs.json，读取各任务回执；统一 UTC → Asia/Shanghai。异常 JSON、半写入 JSONL 不变成 0；保留最后成功快照并提示延迟。
  2. 采集层：为候选与发布阶段新增 append-only 事件日志，记录 event_id、时间、job_id、source_id、阶段、结果；逐模型调用写入独立 usage 账本。SQLite 聚合缓存建立唯一索引，重复扫描、断点恢复不重复计数。
  3. 只读 API：GET /api/overview?date=YYYY-MM-DD、/api/stages、/api/videos?kind=candidate|publish、/api/runs/:id。返回时区、快照时间、数据质量、缺失项及分页信息。读取端不调用 audit/update，也不自动改变队列。
  4. 正式界面：日期选择默认今天；每 30 秒刷新；数据超过两轮未更新显示延迟；明细可筛任务和状态；本地视频由受限资源路由预览，来源与公开笔记使用已有真实 URL。
  5. 安全与部署：默认监听 127.0.0.1；仅暴露白名单文件，不返回 Cookie、凭据或任意磁盘路径。共享部署需另行设计身份与本地数据同步。

05 / 开发顺序与验收

第一步：业务聚合与今日明细，Token 显示未采集。第二步：按实际执行宿主实现 usage 适配器和阶段关联。第三步：实时刷新、任务钻取和数据质量告警。本轮原型无需安装框架。

验收覆盖：北京时间午夜边界；同一素材重复入池；今日入池后今日发布仍保留入池数；历史 JSONL 重复或状态更正；缺链接但确认发布；unconfirmed 不算成功；恢复任务与模型重试不丢不重；缓存和推理子集不重复相加；跨日调用；空数据与损坏文件；部分用量与完全未采集；共享调用保留未归因。

现状核对（2026-11-16）：publication_queue.py 写入 enqueued_at；publish_history.py 写入 published_at；Skill 脚本不直接调用模型，未发现 Token 账本。视觉稿中的 12 条、5 条、128.4k、18.6k 均为设计示例。
