# 热点文章视觉设计与人工审核

本参考只负责视觉与格式，不改变 `zailushang-article` 的正文所有权。视觉工作不得修改观点、事实、案例、论证顺序或语言习惯。

## 视觉模式

- `rich`：默认出版级流程。必须有经过像素审核的 `hero.png`、独立 `visual-plan.md`、正文候选配图评估、`article.preview.html` 和 `review.md`。
- `standard`：保留简洁正文排版，封面可选；仍需分离粘贴版与完整预览，并完成手机视口检查。
- `text`：用户明确选择纯文字时免封面；仍需说明零正文配图的理由和手机阅读节奏。

`--missing-materials skip` 不免除 `rich` 的视觉工作。封面和信息图可以基于已核实内容生成，但不得伪造产品截图、数据、模型界面或作者证据。

## 统一视觉系统

在 `visual-plan.md` 中先确定一组设计令牌，再制作任何资产：

- 主色、辅助色、正文色、次要文字色、浅色背景、边框色，均使用十六进制颜色。
- 正文字号、行高、段落间距、H2/H3 层级、引用块、表格、列表和代码块样式。
- 新闻播报可使用时间线、模型定位图和对比表；深度文章可使用判断框架、流程图和风险表。
- 一套文章只使用一个主视觉方向，不让封面、正文配图和结尾块各自成为无关模板。
- 禁止抽象 AI 大脑、随机代码雨、通用科技背景、无信息渐变、营销式卡片堆叠和只为装饰的 SVG。

## 读者视角的扫描与层级

排版首先要回答读者三个问题：这条文章讲什么、和我有关的更新在哪里、下一步该做什么。不能只检查 HTML 是否兼容。

- 首屏保留具体开头，并让读者尽早看到 2–3 条新闻索引或核心判断。多条新闻埋在一个长句里时，可在 `article.md` 中改成简短列表，但不得新增事实、改变顺序或制造额外摘要。
- 首段可使用 17px 引导字号，正文保持 16px 和约 1.85 行高；不要通过缩小字号塞入更多内容。
- 一个长 H2 章节出现多个独立问题时，可用 H3 提供扫描锚点，例如“断点续扫与批量预算”“补丁受阻原因”。H3 服务于读者定位，不按段落数机械生成，也不把每个小段落都标题化。
- 核心判断最多使用一个引用块，内容必须来自 canonical Markdown；不得为了装饰增加第二套总结。
- 行动清单优先采用“加粗动作标题 + 换行说明”的结构，让读者先扫动作，再决定是否阅读细节。
- 图片、H2/H3、列表、引用和代码应形成交替的阅读锚点。连续长段落需要拆分时，只调整 canonical 结构，不改变措辞、事实和论证顺序。
- 任何列表化、标题化或引用化处理都必须同步写回 `article.md`，再生成两个 HTML 版本，禁止只在 HTML 中增加可见内容。
- 手机审核除首屏和溢出外，还要实际检查：能否快速找到各条新闻、长章节是否有定位点、配置与行动建议是否能扫读、资料来源是否易于识别。

## 封面

`rich` 模式必须生成并审核本地 `hero.png`，除非用户显式切换到其他模式。

1. 从已确认设计提取核心对象、核心场景和核心判断，封面只承担信息流识别，不代替正文论证。
2. 真实素材优先：用户授权素材 → 官方产品图或官方页面截图 → 明确开放许可图片 → 合规公开网页截图。记录来源和授权依据，不使用来历不明的第三方图片。
3. 没有高相关且可发布素材时，才可使用本地生成图形或 AI 回退。生成方向必须包含具体对象或场景，不得只写“生成一张 AI 科技封面”。
4. 至少制作两个真正不同的构图方向，变化应体现在视觉层级、对象或场景，不只是换颜色。
5. 输出选定 `hero.png`、实际信息流缩略图和至少两个安全裁切版本。逐个查看像素，检查主体是否完整、标题是否可读、裁切是否丢失关键信息。
6. 封面属于发布字段，不插入 body-only `article.html`；在 `article.preview.html` 的发布字段区和 `review.md` 中展示。

## 正文配图净收益

技术、产品、新闻和决策文章至少评估两个正文配图候选，但不是每个 H2 都必须配图。

每个候选记录：放置位置、信息增量、证据来源、手机阅读成本、选择或拒绝理由。只有信息增量为正且内容有证据支持时才制作；零正文配图可以成立，但每个候选必须有具体拒绝理由，并通过手机节奏检查。

可选类型：时间线、模型定位图、功能对比、流程、决策框架、风险表、真实且获授权的产品截图。不得编造截图、数据、性能对比或模型能力。

文件型正文图片必须直接出现在 `article.md`：

```markdown
![能够说明图片信息的替代文本](assets/name.png)
```

正文引用 PNG、JPEG、WebP 或 GIF，SVG 只作为可编辑源文件。图片使用包内相对路径和有用 alt 文本，不使用绝对路径、`file://` 或远程临时 URL。

## 粘贴版与预览版

`article.html` 是公众号正文片段：

- 首行使用 `<meta charset="utf-8">`，其余为单个外层 `<section>`。
- 第一个可见文本必须是 `article.md` 的 canonical 开头，不插入 H1、封面、平台摘要、字数、阅读时长或互动占位。
- 使用内联样式，禁止完整 `<html>`、`<head>`、`<body>`、`<style>`、脚本、iframe、`class`、`id`、渐变、阴影、浮动、flex/grid 和外部 CSS。
- 图片、表格和代码必须有防横向溢出样式，保留正文中的链接、图片、列表、表格、引用和代码顺序。

`article.preview.html` 是完整审核页面：

- 使用 `<!DOCTYPE html>`、`lang="zh-CN"`、UTF-8 和 viewport 声明。
- 阅读区首先展示标题和完整 canonical 正文，不截断中段或结尾。
- 阅读区之后才可放置平台摘要、`hero.png`、封面裁切和发布字段。
- 预览的阅读区应接近粘贴版，不得用另一套视觉稿误导审核。

## 人工式内容与格式审核

审核结果写入 `review.md`，内容审核与格式审核分开记录，不能只写“通过”。

内容审核至少包括：核心读者、核心观点、事实来源、用户报告与官方确认的区分、时效边界、版权、个人经历占位、是否存在夸大或 AI 套话。

格式审核至少包括：封面主体与裁切、正文配图净收益、首屏信息、H2 扫描路径、段落密度、表格/代码/图片溢出、中文编码、行动清单、资料来源、粘贴版与预览版边界。

浏览器可用时，实际查看 390×844 或相近手机视口的首屏、完整正文、正文图片和封面缩略图，并在 `review.md` 记录实际观察、问题和修复结果。不能只依据 HTML 标签合法就宣称视觉通过。

## 修复边界

- 正文问题交回 `zailushang-article`，最多两轮定向修改。
- 封面只修改构图、裁切、缩放、对比度，最多两轮。
- 标签、样式、图片引用、溢出和预览壳属于机械修复，最多两轮。
- 每轮后重新检查受影响项；不得通过格式修复偷偷改写正文，也不得为赶交付删除事实边界。
